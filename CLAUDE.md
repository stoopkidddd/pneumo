# Pneumo: agent conventions

These rules apply to every coding agent in this repo (Claude Code, omp, Codex or any other). `AGENTS.md` points here.

Pneumo is a self-hosted, end-to-end encrypted Pushbullet replacement: a Hono server on Node, a React PWA, a native Android app, and one S3 bucket.

## Sources of truth, in order

1. `docs/SPEC.md`: the spec. §2 lists locked decisions; don't re-litigate them.
2. `docs/adr/`: decisions made during the build. A deviation from the spec needs an ADR (copy `docs/adr/0000-template.md`) and a `docs/SPEC.md` update in the same PR.
3. `docs/agents/tangled.md`: the proven commands for PRs, review rounds, merges and CI on Tangled.
4. `brand/DESIGN.md` (once it exists): web and Android UI are built to it.
5. The Linear issue you were given: scope, files to touch, acceptance criteria and Verify commands.

The lead agent's process lives in the Linear document "Lead agent playbook — Pneumo" (project Pneumo).

## Workflow

- **All changes reach `main` through Tangled pull requests** ([tangled.org/demi.dev/pneumo](https://tangled.org/demi.dev/pneumo)). Only the lead agent pushes, opens PRs and merges.
- **Implementers never push.** Commit on your branch in your worktree and stop. Never open or comment on PRs, and never touch Linear, Tangled, GitHub, Railway or any deployed system.
- Stay inside the issue's scope. List follow-ups in your report instead of doing them. Do not design for rare or future cases nobody asked about.
- Match the surrounding code: naming, comment density, idiom.
- **Commit style:** `M<n>: <imperative summary> (ENG-xx)`, for example `M2: Add pushes route (ENG-251)`. Keep format-only changes in their own commit. Say so in the message when you re-record screenshot baselines or regenerate vectors or fixtures.

## mise is the single entry point

Tools (Node, pnpm, Java) and tasks come from `mise.toml`. Run checks with `mise run check:<lane>` (protocol, server, web, android, infra, brand) and `mise run check` for everything. Slow end-to-end suites are `mise run e2e:<lane>`. Don't invoke tools in a way that bypasses the pinned versions.

## Hot files: one in-flight change per file

Changes to these files conflict easily, so only one open issue may touch each at a time:

- `mise.toml`, `pnpm-workspace.yaml`, root `package.json`, `biome.json`, `tsconfig.base.json`, `CLAUDE.md`
- `packages/protocol/src/**`, `packages/protocol/fixtures/**`, `packages/crypto/vectors/**` (the contract)
- `apps/server/src/app.ts` (route mounting), `apps/server/src/index.ts` (startup wiring), `apps/server/src/config.ts`
- `apps/web/src/App.tsx` / route table, `apps/web/vite.config.ts`, `apps/web/playwright.config.ts`
- `apps/android/gradle/libs.versions.toml`, `apps/android/app/build.gradle.kts`, `apps/android/app/src/main/AndroidManifest.xml`, `ui/PneumoNavHost.kt`, Room (`data/db/**`)
- `Dockerfile`, `docker-compose.yml`, `.tangled/workflows/**`, `railway.json`, `README.md`, `docs/SPEC.md`, `docs/agents/**`
- Generated brand outputs: `apps/web/src/styles/tokens.css`, `…/ui/theme/BrandColors.kt`, icon resources

`pnpm-lock.yaml` is not hot. On a rebase conflict, take `main`'s lockfile, run `pnpm install`, and commit the result as `chore: regenerate lockfile`.

## The contract

`packages/protocol` and `packages/crypto/vectors` are frozen after the M1 gate. Changing them needs an ADR, the spec updated, and every consumer (server, web, Android) updated in the same issue. If you are an implementer, report the problem instead of changing them. Fixtures and vectors are generated by their scripts, never hand-edited.

## Secrets

- No secret goes into git, ever.
- Development uses MinIO with the fake credentials in `.env.example`, copied to `.env.local` (gitignored).
- A new env var goes into the server's zod config schema and `.env.example`, with a fake value. Production values are set by the lead in Railway variables.
- Never print, log, comment or commit a secret, device token, passphrase, master key or presigned URL, not even from tests. Fixed fake passphrases in test code are fine.
- The APK release keystore stays on the owner's Mac and never enters the repo or CI.
